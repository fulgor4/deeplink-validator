# Deeplink checker

A website + API server that follows every redirect of a campaign / deep link and tells you, in plain English:

1. **Valid link for Walmart**: every hop from the pasted domain onward (`click2cart.com → goto.walmart.com → …`), and whether the URL encoding is right (not encoded / encoded once = correct / double or triple encoded, which makes the app open and then bounce to the website), plus spaces, bad `%`, duplicate params, a second `?`.
2. **Opens the Walmart app**: the first hop that is `walmart://…`, `goto.walmart.com` or `https://www.walmart.com`.
3. **Where it lands in the app**: the page each app (iPhone, Android) opens, e.g. "Brand page (brand ID 20084619)".

Two parts, deployed separately:

- **The website** (`public/`, published by GitHub Pages through the root `index.html` redirect) holds all the Walmart logic: the checks, the iPhone / Android route tables and the wording. It runs in the browser.
- **The hops API** (`server/`) only follows the link: HTTP redirects, meta refresh, and JavaScript-only redirect pages run in headless Chrome. It returns the list of hops and holds nothing Walmart-specific. It replaces redirectcheck.org, which can't run JavaScript and is blocked on the Walmart network.

A browser can't follow redirects itself (CORS hides cross-origin redirects from web pages), which is why the hops API exists.

## Layout

```
index.html                 GitHub Pages entry: forwards to public/
public/                    the website (everything a browser loads)
  index.html
  config.js                where the hops API runs (hopsApi)
  js/core.js               all checks + the plain-English summary
  js/app-routes.js         iPhone + Android routers: where a link lands in each app
  js/app-routes-android.generated.js   Android route table (generated by tools/extract-app-routes.mjs)
server/                    the hops API: self-contained, deploy this folder on its own
  server.mjs               HTTP server: GET /api/hops, GET /healthz
  trace.mjs                follows redirects hop by hop (SSRF-safe)
  headless.mjs             runs JavaScript redirect pages in headless Chrome
  package.json, Dockerfile
cli/deeplink-trace.mjs     the full report in a terminal (handy for debugging; uses public/js + server/)
tools/extract-app-routes.mjs   refreshes the route tables from the app repos
test/                      core.test.mjs, server.test.mjs (offline)
serve, deeplink-trace      launchers (prefer Bun, fall back to Node 18+)
```

No `npm install`: there are no dependencies. Optional: Chrome / Chromium / Edge / Brave for JavaScript redirect pages.

## Run it locally

```sh
./serve                 # or: npm start   ->  hops API + the web page on http://127.0.0.1:8080
npm test                # both test suites (the headless-Chrome tests are skipped if no browser is installed)
```

`./serve` sets `SERVE_SITE=1`, so the hops API also serves the web page (same origin, no configuration). It prefers Bun, whose `fetch` honours `HTTP(S)_PROXY` (Node < 24 does not).

## The hops API

```
GET /api/hops?url=<link>[&ua=ios|android|desktop]
  -> { startUrl, hops: [{ index, url, host, status, location, nextUrl, via, appScheme, fallbackUrl, js, … }], finalUrl, stopped, source: "hops-api" }
GET /healthz
  -> { ok: true, service: "deeplink-hops", runsJs }
```

The page turns the hops into the full report itself (`DLCore.buildReport` in `public/js/core.js`), exactly as it does with a redirectcheck.org answer.

| Setting (env) | Default | |
|---|---|---|
| `PORT` / `HOST` | `8080` / `127.0.0.1` | use `HOST=0.0.0.0` in a container (the Dockerfile does) |
| `ALLOWED_ORIGINS` | none = open to everyone | not set or `*`: any web page, curl and scripts can call the API. Set it to a comma-separated list of origins (e.g. `https://fulgor4.github.io`, scheme + host, no path) to allow only those pages; other websites **and requests with no browser origin (curl, scripts)** then get 403. |
| `RATE_LIMIT_PER_MIN` | `100` | per client IP |
| `TRUST_PROXY` | off (`1` in the Dockerfile) | take the client IP from `X-Forwarded-For`. Needed behind a load balancer / reverse proxy (most hosts), otherwise every user shares one limit. Leave off when clients connect directly (they could fake the header). |
| `MAX_INFLIGHT` | `10` | traces at once; each JavaScript page uses one Chrome tab (~100–200 MB) |
| `RUN_JS` | on | `0` = don't run JavaScript pages (pgbuynow is then emulated, others are "unknown") |
| `CHROME_PATH` | auto-detect | `/usr/bin/chromium` in the Dockerfile |
| `CHROME_NO_SANDBOX` | off | `1` only if Chromium's sandbox can't start in your container (it needs user namespaces); this weakens isolation from the pages it runs |
| `ALLOWLIST_ONLY` | off | `1` = only follow Walmart / known redirector hosts |
| `SKIP_DNS_CHECK` | on when a proxy is set | the proxy resolves names |
| `SERVE_SITE` | off (`1` via `./serve`) | also serve `public/` (local development) |

When set, `ALLOWED_ORIGINS` keeps other websites from using your API through their visitors' browsers, and stops casual scripts. It is not a login: a script can fake the headers. Use your host's access control if it must be private.

## Hosting it

1. **Deploy `server/`** anywhere that runs a container or a long-lived Node process, e.g. `docker build -t deeplink-hops server/` and run it with `-p 8080:8080 -e ALLOWED_ORIGINS=https://gecgithub01.walmart.com`. Without Docker: Node 18+ (or Bun) plus Chromium, then `node server.mjs` in that folder. It needs outbound internet access to arbitrary public sites.
2. **Point the page at it:** set `hopsApi` in `public/config.js` (e.g. `"https://deeplink-hops.example.com"`), commit, and GitHub Pages republishes.
3. **Check:** open the page; the note under the button says "followed by the Deeplink Checker's own server". If it mentions redirectcheck.org, the page couldn't reach `<hopsApi>/healthz` (wrong address, or the page's origin isn't in `ALLOWED_ORIGINS`).

Things to decide before sharing it:
1. **Can people reach it?** Walmart's web gateway blocks sites it hasn't categorised (redirectcheck.org returned `403 UncategorizedBlock` on the Walmart network). A newly hosted server outside Walmart will probably need a category request before people on VPN can use it; hosting it internally avoids that.
2. **Outbound access.** Behind a corporate proxy, arbitrary sites may be blocked or need authentication.
3. **Abuse.** It fetches any public URL and runs other sites' JavaScript. Built in: per-IP rate limit, concurrency cap, `ALLOWED_ORIGINS`, refusal of private / link-local addresses (including cloud metadata), non-80/443 ports, credentials and non-http(s), every request the headless browser makes is checked the same way. DNS rebinding is theoretically possible; run it where it has no route to internal services.

## The web page

Paste a link and press **Check link**. The page is written for non-technical people (product managers, advertisers) and answers three questions in plain English, with a green / red / grey result for each:

1. **Valid link for Walmart**: is it a link Walmart can read? (double or triple encoding, a missing destination, spaces, a link that never reaches Walmart, redirect loops, error pages). Problems say what is wrong, what to do, and offer a corrected link to copy when one can be built.
2. **Opens the Walmart app**: does tapping it launch the app, or does it open and fall back to the website?
3. **Where it lands in the app**: one row per app (iPhone, Android) naming the page and the ID the link carries, e.g. "Brand page (brand ID 20084619)". Green = a page or the Home page; amber = the app opens but sends people to the website (or, on Android, never opens because the path isn't in the app's manifest); red = the app shows an error. See *Where it lands in the app* below.

Inside the same card: **The link's journey** (every site the link passes through as `domain…`; hover or click for the full address). When something is wrong, a collapsed **Technical details** section follows, with the full checks for whoever has to fix the link. The words are produced by `friendlySummary()` in `core.js` from the same report the CLI prints, so the CLI and page cannot disagree. There is no "trace with", user-agent or expected-destination setting: the page uses the hops API if `<hopsApi>/healthz` answers as `deeplink-hops` (`hopsApi` from `config.js`, else the address the page was loaded from), otherwise the redirectcheck.org API, and if neither can follow the link it tells the user the checker only works outside the Walmart VPN (and still checks the pasted link itself when that alone finds a problem).

The look borrows the Adtech Tools palette and font stack (blue header band, light page, EverydaySans if installed, otherwise Helvetica Neue / Arial). Technical details are only offered when something is wrong; a clean pass shows just the verdict, the three answers and the journey.


| How the page is opened | Who follows the link | What you get |
|---|---|---|
| GitHub Pages (or any static hosting) with `hopsApi` set and the page's origin in `ALLOWED_ORIGINS` | the hops API | everything, including JavaScript redirect pages |
| from the server itself (`./serve`) | the hops API (same origin) | everything |
| static hosting without a reachable hops API, or `public/index.html` opened as a file | **redirectcheck.org**, if the browser may call it | the report, computed in the browser; no JavaScript redirect pages (pgbuynow filled in, unverified); otherwise the page says it only works outside the Walmart VPN |

### Without the hops API: the redirectcheck.org fallback

The page `POST`s `{url, method:"GET", followMetaRefresh:true}` to `https://www.redirectcheck.org/api/check` and converts the answer (`redirects[].from/to/status_code`, `final_result`) into the same hop list the CLI uses (`chainFromRedirectCheck` in `core.js`), so every check runs unchanged.

Things to know before relying on it:

- **The link leaves your machine.** Campaign links carry click IDs and UUIDs; the service is a third party. Check that is acceptable. The hops API sends it nowhere else.
- **CORS is not guaranteed.** The call only works if the API answers with `Access-Control-Allow-Origin` for your page's origin. Check from a network that can reach it: `curl -si -X OPTIONS https://www.redirectcheck.org/api/check -H 'Origin: https://your-page.example' -H 'Access-Control-Request-Method: POST' -H 'Access-Control-Request-Headers: content-type' | grep -i '^access-control'`. If the headers are missing, the page shows an explanatory error; use the hops API.
- **Corporate web gateways may block it** (it returned `403 UncategorizedBlock` from the Walmart network when tested), in which case colleagues on VPN get the same error. That is a network policy decision; ask for the site to be reviewed rather than working around it.
- **It runs no JavaScript.** Redirect pages that use JavaScript are reported as "unknown", not as a failure, except `openapp.pgbuynow.com`, whose known behaviour is filled in and marked as not checked against the live page. The hops API runs them for real (see *JavaScript redirect pages*). A final `www.walmart.com/blocked?…` is Walmart's bot wall and is shown as info.

## Where it lands in the app

`public/js/app-routes.js` ports both apps' routers and runs them on the hop where the app opens:

| | iPhone (glass-app) | Android (walmart-glass) |
|---|---|---|
| Table | 491 legacy + async patterns, **hand-curated** in `app-routes.js` (they're registered in many code styles) with the file each comes from | 428 `@GlassLinkPattern` regexes + the manifest intent filters, **generated** into `public/js/app-routes-android.generated.js` |
| Before matching | goto → `ImpactLink` (u= decoded once); www.walmart.com → `walmartSchemeURL`; exact-URL redirect table; `/es/` strip; `gbo=1` → Safari | rewrite chain (redirect map, `walmart1h`, `/es/`, pharmacy / health & wellness rewrites); goto → follows the redirects and uses the last real app page (like `GotoLinkResolver`) |
| Matching | legacy `PatternMatcher`, first match in registration order (`:x` one segment, trailing `*` any number). The async router is shown as "would open X instead" because it's off by default (CCM `platform.deeplinking.asyncRouter.enabled`) | anchored regex on the path; exactly one link class must match (the `@Last` catch-all drops out) |
| No match | universal link → **Safari** (website); `walmart://` → app stays on Home | walmart.com path missing from the manifest → app **never opens**; matched only by the catch-all → **browser**; nothing matches → Home |

Refresh after pulling either app (both repos next to this one by default):

```sh
npm run routes      # node tools/extract-app-routes.mjs [--android ../walmart-glass] [--ios ../glass-app]
```

It rewrites the Android table and checks that every iOS pattern still appears in the file it cites (listing any that don't, so you can update `app-routes.js`). The tables reflect whatever branch each repo has checked out; the page/CLI show the Android source commit.

Limits: feature flags and server config (CCM) are not known here, so flag-gated routes (e.g. pharmacy / health & wellness) are shown as if on, with a note; "may ask to sign in" comes from the Android link class's `requiresAuth`.

## JavaScript redirect pages

Some redirectors (e.g. `openapp.pgbuynow.com`) answer `200` with a page whose script builds the next address at runtime. The hops API (and the CLI) run such pages in **headless Chrome** (Chromium, Edge and Brave also work; `CHROME_PATH` to pick one) as an iPhone and record where the page tries to send the visitor: a top-level navigation, a hidden `walmart://` iframe, `window.open`. Nothing is opened or followed by the browser: each navigation is recorded and cancelled, then the tracer follows it with plain HTTP, so status codes and raw `Location` headers stay exact. No npm packages are needed (it talks to Chrome over the DevTools pipe).

- Chrome only starts when a hop is a JavaScript-only page (about 2 s per such page). Pages with a static redirect (HTTP 3xx, meta refresh, literal `location = "…"`) and walmart.com pages are never run.
- Every request the page makes passes the same checks as the tracer (http/https on 80/443, public addresses only); others are blocked.
- If no browser is found, or with `--no-js` / `RUN_JS=0`, `openapp.pgbuynow.com` is emulated from its known code and other JavaScript pages are reported as unknown.
- Pages that wait for a tap or detect headless browsers can still come back as unknown ("didn't send the visitor anywhere, even after running its JavaScript"). The page is run as an iPhone; pages that branch by device may send Android elsewhere (the Android row is then judged on the web address).
- The static web page (no server) can't do this: redirectcheck.org runs no JavaScript.

## Corporate proxy

If `HTTPS_PROXY` / `HTTP_PROXY` is set the tool skips local DNS (the proxy resolves names) automatically; override with `SKIP_DNS_CHECK=0|1`. **Node before v24 ignores proxy variables in `fetch`**, so on a proxied machine use Bun (the launcher prefers it), or Node ≥ 22.21 / 24 with `NODE_USE_ENV_PROXY=1`. If the first hop shows `ENOTFOUND`, `407` or "Unable to connect", that is the network, not the link.

## Limits

- JavaScript redirect pages are run in headless Chrome when one is installed (see above); otherwise only meta-refresh / literal `location = "…"` are followed and `openapp.pgbuynow.com` is emulated from its known page code. Whether the app actually opens is **inferred, not observed**: only `goto.walmart.com` is a verified `applinks:` domain, so check on a device.
- The page each app lands on comes from ports of the two routers (see above), not from running the apps; flag-gated routes and server-side config can change the real result. Confirm on a device for anything unusual.
- It makes real GET requests to every hop: don't trace links that change state on GET. Private/link-local addresses, non-80/443 ports and URL credentials are refused. With a proxy, the proxy must itself refuse internal targets.

## CLI (for debugging)

```sh
./deeplink-trace 'https://click2cart.com/pdp?...'            # full report
./deeplink-trace '<url>' --paths-only                        # just the redirects
./deeplink-trace --help
```

Always **single-quote the URL** (it contains `&` and `?`).

| Option | |
|---|---|
| `--paths-only` | call path only |
| `--json` | machine-readable |
| `--expect brand:ID` / `ip:ID` / `cp:ID` / `path:grocery` | check the final route |
| `--ua ios\|android\|desktop\|"<ua>"` | redirectors often branch on platform; default iOS |
| `--max-hops N` | default 10 |
| `--allowlist-only` | only follow Walmart / known redirector hosts |
| `--no-js` | don't run JavaScript redirect pages in headless Chrome |

Exit code: `0` no failures, `1` at least one FAIL, `2` bad usage, `3` first host unreachable from your machine (network/proxy, no verdict about the link).
